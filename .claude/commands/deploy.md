description: main ブランチの最新状態を検証したうえで、既存の本番GASデプロイをURLを変えずに更新する
---

使い方: `/deploy`（引数なし）

以下の手順で GAS への本番デプロイを行ってください。PRのマージは対象外です。すでに main にマージ済みであることが前提です。

1. `git status` で作業ツリーの状態を確認する
   - 未コミット・未pushの変更がある場合はデプロイを行わず中断し、内容をユーザーに報告してどう扱うか（コミット/スタッシュ/破棄）指示を仰ぐ
2. `git checkout main` → `git pull origin main` で main を最新化する
   - `git rev-parse HEAD` と `git rev-parse origin/main` を比較し、ローカルの main が origin/main の最新コミットと一致していることを確認する。一致しない場合（pull後もズレが残る等）はデプロイを行わず中断し、状況をユーザーに報告する
3. `npx tsc --noEmit` と `npm run test` を実行する
   - どちらか失敗した場合はデプロイを行わず中断し、原因をユーザーに報告する（このskillでは自動修正しない。修正が必要な場合は `/fix-issue` 等の別フローで対応する）
4. `npx clasp deployments` で現在のデプロイ一覧を取得し、`@HEAD` ではない（バージョン固定の）デプロイを本番デプロイとして特定する
   - 該当するデプロイが0件、または複数件見つかった場合は自動判定せず中断し、一覧をそのままユーザーに提示して本番デプロイのIDを確認する
5. デプロイ内容の確認
   - `git log` で直近のコミット（特に前回デプロイ以降の差分がわかる範囲）を確認し、今回デプロイされる変更内容の要約をユーザーに提示する
   - 実際に本番へ反映する前に、必ずユーザーに実行してよいか確認を取る（このステップは省略しない）
6. ユーザーの承認を得たら `npm run push`（`clasp push`）でコードを反映する
7. `npx clasp deploy -i <手順4で特定した本番デプロイID> -d "<説明: 日付とデプロイ対象コミットのSHA・要約>"` を実行し、既存の本番デプロイを新バージョンで更新する
8. デプロイ結果（新バージョン番号・デプロイID・反映したコミットSHA、および手順2で確認した「origin/main の最新コミットである」旨）を簡潔に報告し、LINE実機（Webhook応答・LIFF画面・リッチメニュー等）での動作確認をユーザーに促す

制約:
- `clasp deploy` を `-i` なしで実行し新規デプロイを作成することは絶対に行わない（URLが変わり、LINE WebhookやLIFFのEndpoint URL設定が壊れるため）
- 型チェックまたはテストが失敗した状態ではデプロイしない
- 未コミット・未pushの変更が残った状態のmainをデプロイしない
- force push・`git reset --hard`・`git clean` などの破壊的なgit操作は行わない
- 手順6・7（実際にproductionへ反映する操作）は、必ずユーザーの明示的な承認を得てから実行する。このskillは自動実行フロー（loop等）から呼ばれる場合であっても、この承認ステップを省略しない
- スクリプトプロパティの追加・変更、LIFF設定、リッチメニュー構造の変更が必要な場合はこのskillの対象外。気づいた場合はデプロイを進めず状況を報告する
- 各ステップの結果を簡潔に報告する
